How login works: option A vs option B

Both use Supabase as the Postgres database. They differ in who checks the password and what the browser holds afterwards: a session cookie (A) or a Supabase token (B).

Option A

Spring Security handles login

Recommended

Spring checks the password and keeps a session. The browser only holds a cookie with a random session ID. Supabase is just the database, and its Auth feature stays off.

Option B

The page logs in with Supabase Auth

The page signs users up and logs them in through Supabase's JavaScript library, without Spring. Spring only checks the token on later requests.

What the browser holdsHttpOnly cookie with a random session ID. JavaScript can't read it.A JWT and a refresh token in localStorage. Any script on the page can read them.
