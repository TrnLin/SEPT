# User stories and acceptance criteria

## Story format

**As a** <who>, **I want** <what>, **so that** <why>.

## Acceptance criteria

Describe the result, not how it is built. Each criterion must clearly pass or fail. One common format:

```
Given <starting situation>
When <action>
Then <observable result>
```

## INVEST check (every Sprint 1 story)

| Letter | Question |
|---|---|
| Independent | Can it be built without waiting for another story? |
| Negotiable | Is it a goal, not a fixed design? |
| Valuable | Does a user or the client get something from it? |
| Estimable | Can the team estimate it? |
| Small | Does it fit in one sprint? |
| Testable | Do the acceptance criteria give a clear pass or fail? |

## Tasks

Split each Sprint 1 story into tasks of 1–3 hours. Avoid any task over 8 hours.

## Board labels

Story, Task, Bug, plus enhancement and documentation where they fit.

## Rubric target

All Sprint 1 stories, plus at least 15 more well-defined stories in the product backlog.
